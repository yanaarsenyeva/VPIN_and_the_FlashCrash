# VPIN and the Flash Crash

Самостоятельная реализация методов из статьи Torben G. Andersen
и Oleg Bondarenko «VPIN and the Flash Crash».

## Цель

Реализовать базовый TR-VPIN, воспроизвести выбранные результаты
статьи при наличии подходящих данных и провести дополнительную
проверку устойчивости.

## План работы

1. Выбор и проверка реальных данных.
2. Построение минутных баров.
3. Классификация объёма по tick rule.
4. Построение бакетов фиксированного объёма.
5. Расчёт базового TR-VPIN.
6. Тестирование реализации.
7. Сопоставление результатов со статьёй.
8. Дополнительная проверка устойчивости.

## Статус данных

В исходной статье используются транзакционные данные
E-mini S&P 500 futures за январь 2008 — июль 2010.

Окончательный источник данных для проекта пока не выбран.

Кандидатный датасет Kaggle с обозначением SP прошёл первичный
аудит, но пока не подтверждён как подходящая выборка сделок ES.

Необходимо установить:
- точное название инструмента;
- смысл поля volume;
- причину нулевых объёмов;
- полноту торговых записей;
- часовой пояс.

До завершения проверки этот датасет не используется для
заявлений о воспроизведении результатов статьи.

Синтетические данные в проекте не используются.

## Структура проекта

- data/ — документация по данным; сами рыночные файлы хранятся локально.
- notebooks/ — исследовательские ноутбуки.
- src/ — реализация методов.
- tests/ — проверки корректности.
- reports/ — итоговые таблицы и графики.




## Основные результаты

Мы проверяем выбранные методы Andersen–Bondarenko на сделках
BTCUSDT Binance Spot за январь–март 2020 года.

Это проверка на новом рынке, а не воспроизведение Flash Crash
6 мая 2010 года. Январь–февраль используются для обучения,
март — для оценки прогнозов.

| Проверяемый вопрос | Что сделали | Что получили |
|---|---|---|
| Связан ли TR-VPIN со структурой торгового объёма? | Сравнили TR-VPIN с U2-VPIN на бакетной и часовой сетках. | На часовой сетке корреляция составила 0.906 в январе–феврале и 0.933 в марте. |
| Даёт ли TR-VPIN дополнительную прогнозную информацию? | Добавили TR-VPIN к регрессии с прошлой волатильностью и объёмом. | В основном эксперименте MSE на марте снизилась на 0.71%, но модель уступила прогнозу Persistence. |
| Помогает ли биржевое направление сделок? | Построили Exchange-side VPIN и оценили его на тех же прогнозных часах. | Его добавление к контрольной регрессии практически не изменило MSE. Добавление к модели с TR-VPIN не дало убедительного преимущества в выполненной bootstrap-проверке. |
| Зависят ли результаты от параметров? | Проверили окна L = 25, 50, 100 и размеры бакета 0.5V, V, 2V в отдельных экспериментах. | Величина дополнительного эффекта менялась; преимущество Persistence сохранялось во всех проверенных вариантах. |

Persistence — прогноз, равный реализованной волатильности
предыдущего часа.

### Ограничения интерпретации

- Выводы относятся к выбранным данным, горизонту и моделям.
- Высокая корреляция не доказывает причинность.
- Расширения анализировались после просмотра мартовских результатов.
- Bootstrap-интервалы условны на обученных моделях и наблюдаемом
  тестовом периоде.
- Exchange-side VPIN отличается от базового метода как источником
  направления сделки, так и обработкой покупок и продаж внутри минуты.
- Лучшие параметры на марте не заменяют заранее выбранную
  базовую спецификацию.


  ## Установка и запуск

### 1. Скачать проект

```bash
git clone [https://github.com/yanaarsenyeva/VPIN_and_the_FlashCrash.git](https://github.com/yanaarsenyeva/VPIN_and_the_FlashCrash.git)
cd VPIN_and_the_FlashCrash
```

### 2. Создать Python-окружение

Команды ниже приведены для macOS/Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-lock.txt
```

### 3. Скачать исходные данные

Официальный каталог:

https://data.binance.vision/?prefix=data/spot/monthly/trades/BTCUSDT/

Необходимые файлы:

- BTCUSDT-trades-2020-01.zip
- BTCUSDT-trades-2020-02.zip
- BTCUSDT-trades-2020-03.zip

Распаковать CSV и разместить их в:

```text
data/raw/binance/
```

Ожидаемые имена:

```text
BTCUSDT-trades-2020-01.csv
BTCUSDT-trades-2020-02.csv
BTCUSDT-trades-2020-03.csv
```

Исходные и промежуточные данные не включены в репозиторий.
В выполненном исследовании контрольные суммы исходных ZIP
не проверялись.

### 4. Выполнить ноутбуки по порядку

Каждый ноутбук запускать с чистого ядра, используя окружение проекта:

1. notebooks/00_environment_check.ipynb
2. notebooks/02_binance_data.ipynb
3. notebooks/03_vpin_analysis.ipynb
4. notebooks/04_trade_classification.ipynb
5. notebooks/05_forecast_uncertainty.ipynb
6. notebooks/06_window_robustness.ipynb
7. notebooks/07_bucket_robustness.ipynb

### 5. Запустить тесты

После подготовки данных:

```bash
python -m pytest tests/test_tr_vpin.py -q
```

Тесты используют подготовленные реальные данные.
Без выполнения этапа подготовки они не запускаются успешно.
